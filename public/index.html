Help and information

Using the apps

  • Pick a tool on the Home tab to open it in a new tab. Switch between tabs whenever you like; each open app keeps its place.
  • Open and save files from each app’s own menus. Files come from and go to your device, and nothing is uploaded to this server.
  • Save to a file often. Browser storage is not a backup, and a crash or cleared browser data can lose unsaved work.
  • You are warned before closing the page while apps are open. You can turn that off, and tab restoring too, under Preferences on the Home tab.
  • When an app is updated, a banner offers to refresh. Save your work first, because refreshing restarts the open apps.

Adding an app (site owner)

  1. Press Manage and sign in with the admin token.
  2. Under Add an app, enter the project’s GitHub address, such as owner/name.
  3. Optionally choose a group (for example Office or Create) and write a short description, then press Add app.
  4. The server finds the project’s latest GitHub release, downloads its web build, unpacks it and adds a tile. This usually takes under a minute, and the list shows progress or the reason it failed.
  5. After that the server checks for new releases by itself and installs them. Visitors see a refresh banner when something changes.
  6. In Manage you can also pick a colour for each group, edit an app, update it now, or remove it.

What an app needs in order to work here

  • A public GitHub repository with a published Release. Tags on their own are not enough.
  • A release file that is a zip of a static website with an index.html. By default the file name must contain -web- and end in .zip. If a project names it differently, use Edit and set the release file pattern.
  • Links that work from a sub-folder. A site that only works at the root of a domain will not load.
  • A size under the limit, 400 MB unless the owner changed it.

Limitations

  • Only browser-based builds work. Desktop installers such as .exe, .dmg, .deb or .AppImage cannot run here.
  • Private repositories are not supported. GitHub limits how often releases can be checked, and the owner can add a GITHUB_TOKEN to raise that.
  • All apps share one web address and so share the browser’s storage. Only add projects you trust.
  • Whether an app recovers unsaved work after a crash depends on the app. The hub only remembers which tabs were open.
  • Every open tab uses memory on the visitor’s device, so close tabs you are not using, especially on phones.
  • Saving to a file on the device needs a secure (HTTPS) connection in most browsers.
