Help and information

Using the apps

  • Pick a tool on the Home tab to open it in a new tab. Switch between tabs whenever you like; each open app keeps its place.
  • Open and save files from each app’s own menus. Files come from and go to your device, and nothing is uploaded to this server.
  • Save to a file often. Browser storage is not a backup, and a crash or cleared browser data can lose unsaved work.
  • You are warned before closing the page while apps are open. You can turn that off, and tab restoring too, under Preferences on the Home tab.
  • A banner offers a refresh when an app is added, updated or removed. Save your work first, because refreshing restarts the open apps.
  • A small arrow beside a version number means a newer version exists that the site owner has not installed yet.

If an app will not open or looks blank

When an app cannot start, a red bar appears above it with the reason. Try these in order:

  1. Press Reload this app in the bar, or refresh the page.
  2. Make sure the address starts with https://. Many browser features, including saving to your device and fast graphics, only work on secure pages.
  3. Use an up-to-date Chrome, Edge, Firefox or Safari. These apps run as WebAssembly and need WebGL or WebGPU for graphics. Turn on hardware acceleration in your browser settings if it is off.
  4. Close other tabs and apps, especially on phones and tablets. Each open app uses memory.
  5. If the bar says a file is missing, the problem is in how the project packaged that release. The site owner can choose another version in Manage, and the project’s maintainers can fix it in their next release.

What the hub fixes on its own

  • It finds the web build even when a project names its files differently, and skips installers for Windows, macOS and Linux.
  • It checks every download before using it. If a file the app needs is in the wrong folder, it is moved into place.
  • If the newest release is broken, the hub keeps or installs the newest one that works, remembers the broken one so it is not downloaded again, and tells the owner why in Manage.
  • Sites built for the root of a domain have their main links adjusted so they load from here.
  • Icons are taken from the app itself, or from the project’s repository, and a lettered tile is used if none is found.
  • Routine log messages from apps are hidden so the browser console shows warnings and errors only.

Adding an app (site owner)

  1. Press Manage and sign in with the admin token.
  2. Under Add an app, enter the project’s GitHub address, such as owner/name. Optionally choose a group, a short description, a release file pattern or an icon address.
  3. Press Add app. The server finds the project’s releases, downloads the newest web build that works, and adds a tile. This usually takes under a minute, and the list shows progress or the reason it failed.
  4. After that the server checks for new releases by itself. Each app has an Update automatically switch. When it is off, the list shows that an update is available and you press Update when you are ready.
  5. To stay on a particular version, choose it in the version list and press Pin. A pinned app never changes until you unpin it, but the list still tells you when something newer exists.
  6. Under Groups you can rename a group, which moves every app in it, and choose its colour. Use Edit on an app to change its details.

What an app needs in order to work here

  • A public GitHub repository with a published Release. Tags on their own are not enough.
  • A release file that is a zip of a static website with an index.html. The hub recognises the usual -web- name and other web-looking zips. If a project’s file is named differently, use Edit and set the release file pattern.
  • Links that work from a sub-folder. Sites that need to sit at the root of a domain may not load.
  • A size under the limit, 400 MB unless the owner changed it.

Limitations

  • Only browser-based builds work. Desktop installers such as .exe, .dmg, .deb or .AppImage cannot run here.
  • Private repositories are not supported. GitHub limits how often releases can be checked, and the owner can add a GITHUB_TOKEN to raise that.
  • All apps share one web address and so share the browser’s storage. Only add projects you trust.
  • Whether an app recovers unsaved work after a crash depends on the app. The hub only remembers which tabs were open.
  • If every recent release of a project is broken, the app cannot be installed until the project publishes a fixed one.
  • Saving to a file on the device needs a secure (HTTPS) connection in most browsers.
